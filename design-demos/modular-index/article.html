这篇指南关注一件事：怎样把本地的 Markdown 和配置文件，可靠地变成任何人都能通过域名访问的网站。

UPDATE / 2026

本站现已迁移到 GitHub Pages。推送源码后自动构建，不再需要云服务器持续运行静态页面。

01

PREPARATION

前提准备

准备域名和 GitHub 仓库。文章使用 Markdown 编写，配置文件描述网站名称、URL、路径和构建方式。

02

DECISION

选择部署方案

GitHub Pages零运维静态博客
云服务器需要维护后端服务
Vercel / Netlify预览方便前端应用
03

BUILD

生成静态文件

锁文件保证依赖版本一致，构建命令负责生成最终页面。输出目录可以随时重建。

npm ci
npm run build
npm run dev
04

VERIFICATION

上线与验证

检查 HTTPS、域名跳转、核心页面状态码和手机布局。保留迁移前标签，确保出现问题时可以回退。

  • 200 / 首页
  • 200 / 文章页
  • HTTPS / 强制启用
  • CNAME / aitechflow.cn
