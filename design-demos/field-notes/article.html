更新：本站已经改用 GitHub Pages，不再依赖云服务器运行静态页面。

这不是一份只给出命令的教程。先理解各部分如何协作，遇到问题时才知道应该检查域名、构建还是托管设置。

01 / PREP

前提准备

开始之前，需要准备一个域名，以及保存文章源码的 GitHub 仓库。静态博客不需要数据库，生成后的文件可以直接由托管平台提供访问。

现场结论

如果网站只有静态页面，GitHub Pages 能减少服务器费用和日常维护。

02 / DECISION

方案比较

方案维护成本用途
GitHub Pages低静态博客
云服务器高需要后端服务
Vercel / Netlify低前端应用
03 / BUILD

生成静态网站

Markdown 是内容源文件，构建命令负责生成 HTML。生成目录可以随时重建，因此不需要提交到主仓库。

# 安装依赖
npm ci

# 生成静态文件
npm run build
04 / CHECK

上线与验证

部署完成后依次检查 HTTPS、域名跳转、首页、文章页和手机布局。最后保留一个可回退的版本标签。

PASS

核心页面可访问、自定义域名有效、线上文件与本地构建一致。
