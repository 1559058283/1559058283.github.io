建站不是把一串命令依次执行完。理解域名、源码、构建产物和托管平台各自负责什么，出现问题时才知道应该从哪里检查。

01 / BEFORE

开始之前

个人技术博客的内容通常写在 Markdown 文件里，由静态生成器转换为 HTML。最终页面不依赖数据库，因此可以部署到 GitHub Pages 这类静态托管平台。

先做一个选择

如果网站只有文章和静态页面，优先选择 GitHub Pages；只有需要后端服务时，再保留云服务器。

02 / DECISION

选择部署方案

方案维护适合
GitHub Pages低静态博客
云服务器高后端服务
Vercel / Netlify低前端应用
03 / BUILD

生成静态网站

源码仓库保存主题、配置和 Markdown 文章。每次提交后，自动化任务重新生成公开页面，让源码始终成为唯一可信来源。

# 安装依赖并生成页面
npm ci
npm run build

# 在本地检查
npm run dev
04 / CHECK

上线与验证

部署任务显示成功只是第一步。还需要检查自定义域名、HTTPS、首页、文章页与手机布局。

  • ✓核心页面返回正常
  • ✓自定义域名使用 HTTPS
  • ✓手机阅读宽度合理
  • ✓保留可回退版本
